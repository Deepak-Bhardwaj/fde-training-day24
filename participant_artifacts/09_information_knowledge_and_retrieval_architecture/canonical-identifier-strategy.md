# Canonical Identifier Strategy

**Case:** Fleet Disruption & Voyage Recovery Intelligence Workbench
**Stage:** 09 — Information, Knowledge & Retrieval Architecture (Sub-layer B: Semantic Foundation)
**Participant status:** COMPLETED
**Deliverable form:** Structured analysis / specification

## Stage question
How does enterprise evidence become canonical meaning, connected knowledge and runtime context?

## Why this artifact exists
To define how entities are uniquely identified across the shore platform, the vessel edge, and external sources, ensuring referential integrity during offline blackouts (GS-14) and preventing duplicate processing (GS-07).

## Upstream dependency
Use the completed Stage 09 Canonical Entity Model and Stage 06 Provenance Baseline.

- `evidence/04_policy_authority/source_authority.yaml`

## Case challenge
Identifiers must be deterministic and resolvable offline. Relying on a centralized, auto-incrementing database ID will fail during vessel-to-shore network partitions.

## Minimum content

| Entity / Event Type | Identifier Strategy | Composition / Logic | Conflict Resolution (e.g., GS-04) | Offline / Sync Behavior | Evidence |

| **Vessel Identity** | Canonical UUID | Sourced exclusively from SRC-FMS (Fleet Registry). | AIS aliases are mapped to this UUID via a lookup table. AIS UUIDs are rejected as canonical. | Vessel edge caches the FMS UUID mapping table. | `source_authority.yaml` |

| **Constraint (Port/CMMS)** | Composite Key | `source_id + external_reference_id + version_hash` | If SRC-PORT API and Notice conflict, they share the `external_reference_id` but have different `source_id` and `version_hash`. | **Recovery Option** | UUID v4 | Generated by the Deterministic Engine or AI component. | N/A (Options are drafts, not canonical facts). | Drafts generated offline are synced to shore upon reconnect for audit logging. | `canonical-entity-model.md` |
| **Policy Rule** | Versioned ID | `policy_id + version_number` | Superseded rules retain their ID but `status` changes to SUPERSEDED. | Vessel edge caches only ACTIVE policy versions. | `source_authority.yaml` |
