## Stage question
How does enterprise evidence become canonical meaning, connected knowledge and runtime context?

## Why this artifact exists
To define the strict state machines and lifecycle transitions for the core runtime entities (Constraints, Disruptions, Recovery Options). This ensures the system cannot enter invalid states (e.g., executing an unapproved plan, or using an expired constraint).

## Upstream dependency

## Case challenge
State transitions must be explicitly guarded. For example, a `RecoveryOption` can ONLY transition to `APPROVED` if the actor is the `Master`. It cannot transition to `EXECUTED` without passing through `APPROVED`.

## Minimum content

### 1. Constraint Lifecycle
- **INGESTED:** Raw data received from source.
- **VERIFIED:** Passed ACL validation and NLP confidence check (or manual Controller review).
- **ACTIVE:** Currently within `valid_until` window and `status != EXPIRED`. (Usable by engine).
- **STALE:** `current_time` approaching `valid_until`. (Flagged in UI).
- **EXPIRED:** `current_time > valid_until`. (Removed from engine context).

### 2. Disruption Lifecycle
- **DETECTED:** Telemetry or source alert triggered.
- **RECONCILING:** System gathering constraints and building context.
- **MANAGING:** Active recovery options being generated and reviewed.
- **RESOLVED:** Master approved and executed a plan, or disruption window passed.

### 3. Recovery Option Lifecycle (Strict Governance)
- **DRAFT:** Generated by engine/AI. `ai_draft_flag` may be true. Cannot be executed.
- **FEASIBLE:** Passed deterministic engine checks (no CMMS holds violated).
- **INFEASIBLE:** Failed engine checks. Dead end.
- **PENDING_APPROVAL:** Selected by Fleet Controller, routed to Master.
- **APPROVED:** Master explicitly signed off. (Requires `Master` role authority).
- **REJECTED:** Master vetoed. (Requires `Master` role authority).
- **EXECUTED:** Vessel systems confirm action taken. Immutable audit state.

### 4. Invalid State Transition Guards
- **Guard 1:** `DRAFT` -> `EXECUTED` is **FORBIDDEN**. Must pass through `APPROVED`.
- **Guard 2:** `INFEASIBLE` -> `PENDING_APPROVAL` is **FORBIDDEN**.
- **Guard 3:** `APPROVED` -> `DRAFT` is **FORBIDDEN**. Once approved, the state is immutable for audit.
