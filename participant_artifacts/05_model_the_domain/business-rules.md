## Minimum content

| Rule ID | Rule Name | Description | Enforcement Mechanism | Evidence |
| :--- | :--- | :--- | :--- | :--- |
| **BR-01** | Master Veto Authority | No recovery option or navigational change may be executed without explicit approval from the Master. | System must require a digital or procedural sign-off from the Master role before committing any action. | `role_authorization_matrix.csv` |
| **BR-02** | Technical Hold Absolute | If a Critical Maintenance Hold is active in the CMMS, any recovery option violating this hold is immediately marked as INFEASIBLE. | Deterministic constraint engine must reject any plan overlapping with an active hold. No overrides permitted. | `source_inventory.csv`, `role_authorization_matrix.csv` |
| **BR-03** | AI Non-Authoritative Precedence | Any output, suggestion, or draft generated by an AI/LLM component is strictly advisory and holds zero decision authority. | UI must clearly label AI outputs as "Draft/Recommendation". System cannot auto-commit AI-generated actions. | `source_authority.yaml` |
| **BR-04** | Active Policy Exclusivity | Only documents with `status = ACTIVE` in the Fleet Policy Repository may be used to validate recovery options. | Retrieval layer must apply a hard filter: `WHERE status = 'ACTIVE'`. Superseded docs are hidden from active logic. | `source_authority.yaml` |
| **BR-05** | Temporal Idempotency | Duplicate or replayed events from the telemetry stream must be identified and processed exactly once, preserving the original event's temporal provenance. | Ingestion layer must deduplicate based on a composite key of (SourceID, EventID, OriginalTimestamp). | `source_inventory.csv` (SRC-TELEM) |
| **BR-06** | Canonical Identity Supremacy | In the event of a vessel identity conflict between AIS observations and the internal Fleet Registry, the Fleet Registry is the sole source of truth. | Entity resolution logic must weight FLEET_REGISTRY precedence as HIGH and AIS as OBSERVATION only. | `source_authority.yaml` |
